## Staging discipline (D0 step 2)

Confirmed before any commit on this branch:

- `backend/var/ksp_cip.db` and `backend/var/filestore/manifests/seed_manifest.json`
  are pre-existing **tracked** demo artifacts from before V3 (a deliberate
  earlier decision, not this phase's). They are left alone, not re-staged.
- `backend/var/filestore/landing/*.ndjson` — freshly generated by a local
  seed run, **untracked**, and deliberately not staged by any commit in this
  phase.
- No `.env`, no credential, no OAuth token, no `.claude/` artifact is present
  in the working tree.
- Every commit in this phase adds files by explicit path, never `git add -A`
  / `git add .`, specifically so a generated batch or local database cannot
  ride along silently.

## Required Catalyst services — confirmation status

D0 asks to "confirm that the project has the required Catalyst services."
**This cannot be confirmed without a live, logged-in Catalyst project**, which
requires a Zoho account this agent does not have and must not create or log
into on the user's behalf (account creation and OAuth login are user-only
actions per this session's operating rules). The services the application
needs, so the confirmation step is well-defined once a project exists:

| Service | Used for |
|---|---|
| AppSail | `cip-api` (FastAPI/uvicorn), `cip-console` (React) |
| Event Functions | `cip_refresh` (ingest/data_quality/intelligence/retention) |
| Circuit / scheduler | orchestrating the four refresh stages in order |
| Data Store | 47 curated/cip_/ext_ tables — see `catalyst-schema-manifest.json` |
| Stratus | `cip-ingest` bucket — landing/raw/manifests/exports prefixes |
| NoSQL | session state, scratchpad, embedding cache, idempotency (`CatalystKeyValueStore`) |
| Cache | replaceable masters/aggregates only (`CatalystCache`) |
| Authentication | `CatalystIdentityProvider`, mapped to `cip_user_account.external_subject` |
